# PRD.md --- AI 기반 농업용 비료 유출 수질 모니터링 및 대응 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명

**물지킴이 AI (가칭)** --- 농업용 비료 유출 위험 모니터링 및 수질 대응
웹앱

### 1.2 한 줄 소개

하천의 가상 실시간 수질 데이터를 시각화하고, 질산염·인산염 등 영양염류
농도와 환경 지표의 변화를 바탕으로 오염 위험을 알리며, 사용자가 취할 수
있는 관리 방안을 안내하는 교육·시연용 웹앱이다.

### 1.3 문제 상황

농경지에서 사용한 비료의 질소와 인 성분이 강우·배수 등을 통해 하천으로
유입되면 부영양화와 조류 과다 증식에 기여할 수 있다. 조류의 증식과 분해
과정은 수중 용존산소 감소 등 생태계 문제와 연결될 수 있다. 실제 오염
원인은 하수, 축산, 산업 활동 등 여러 요인일 수 있으므로 수질 지표만으로
비료가 원인이라고 단정하지 않는다.

### 1.4 프로젝트 목표

-   센서가 없는 상황에서도 앱을 시연할 수 있도록 **가상 실시간
    데이터**를 생성한다.
-   수질 지표를 대시보드와 그래프로 보여준다.
-   설정된 교육용 기준에 따라 수질 변화와 위험 수준을 표시한다.
-   이상 변화가 나타나면 이해하기 쉬운 설명과 대응 방안을 제안한다.
-   가상 데이터와 실제 측정 데이터를 명확히 구분해 표시한다.

### 1.5 대상 사용자

-   학교 프로젝트 발표자 및 평가자
-   하천 수질 변화를 이해하려는 학생·일반 사용자
-   추후 실제 수질 측정 데이터를 연결하려는 개발자

### 1.6 프로젝트 범위와 한계

이 버전은 **센서와 실제 현장 연결이 없는 프로토타입**이다. 화면의 실시간
수치는 프로그램이 생성한 가상값이며, 실제 하천의 현재 수질을 나타내지
않는다. 따라서 이 앱은 실제 오염을 확정 진단하거나 공공기관의 공식
경보를 대체하지 않는다. 실제 현장 적용 전에는 검증된 센서·검사 자료,
현장별 기준, 전문가 검토가 필요하다.

## 2. 핵심 사용자 시나리오

1.  사용자가 앱에 접속한다.
2.  대시보드에서 선택된 가상 하천 지점의 최근 수질 지표와 마지막 갱신
    시간을 확인한다.
3.  시간에 따라 변하는 가상 수질 그래프를 살펴본다.
4.  질산염 또는 인산염 등 영양염류 값이 설정된 교육용 임계값을 넘으면
    위험 표시와 설명을 확인한다.
5.  앱이 제안하는 예방·대응 방안을 읽는다.
6.  사용자가 시뮬레이션 설정을 변경해 강우량이나 영양염류 유입 수준이
    달라질 때 지표가 어떻게 변하는지 관찰한다.
7.  사용자는 화면에 표시된 데이터가 가상 데이터임을 확인할 수 있다.

## 3. 주요 기능 요구사항

### 3.1 메인 대시보드

-   선택된 가상 측정 지점의 이름 표시
-   **"시뮬레이션 데이터 · 실제 센서 연결 안 됨"** 안내 배너를 항상 표시
-   마지막 갱신 시각 표시
-   현재값 카드: 질산염, 인산염, 용존산소(DO), 탁도, 수온, pH, 강우량
-   각 지표의 단위 표시
-   현재 상태 표시: 정상 범위(교육용), 주의, 높은 위험(교육용)
-   최근 추세 그래프 표시
-   "일시 정지/재개" 버튼으로 가상 데이터 갱신을 제어

### 3.2 가상 실시간 데이터 생성기

-   앱이 열린 동안 일정 간격(기본 3초 또는 5초)으로 가상 데이터 포인트를
    추가한다.
-   새 값은 완전히 무작위로 튀지 않도록 이전 값에 작은 변화량을 더하는
    방식으로 생성한다.
-   강우량 또는 유출 시나리오가 증가하면 영양염류 값이 일정 시간 뒤
    증가할 수 있도록 단순한 교육용 관계를 구현한다.
-   영양염류 값이 높아지는 시나리오에서 DO가 낮아질 수 있는 관계를
    선택적으로 표현하되, 실제 환경의 모든 상황을 대표하지 않는다고
    명시한다.
-   값은 현실적인 범위 내에서 생성하고, 음수 농도 등 잘못된 값은
    허용하지 않는다.
-   최근 데이터는 기본 30\~60개만 화면에 보관해 그래프가 무한히 커지지
    않게 한다.
-   사용자가 "초기화"를 누르면 시뮬레이션을 기본값으로 되돌린다.
-   화면에 표시되는 데이터에는 `SIMULATED` 또는 `가상` 식별자를 둔다.

### 3.3 수질 지표 및 단위

아래는 표시 항목의 권장안이다. 실제 기관 자료를 연결할 경우 해당
데이터셋의 정확한 분석 항목과 단위를 우선한다.

  ----------------------------------------------------------------------------
  지표              설명              표시 단위         주의 사항
  ----------------- ----------------- ----------------- ----------------------
  질산염            물속 질산염 농도  mg/L              질산염(NO₃⁻)인지
                                                        질산성 질소(NO₃-N)인지
                                                        구분 필요

  인산염            물속 인산염 농도  mg/L              인산염(PO₄)인지
                                                        인산염-인(PO₄-P)인지
                                                        구분 필요

  용존산소(DO)      물에 녹아 있는    mg/L              수온과 생태 조건 등에
                    산소                                따라 해석이 달라짐

  탁도              물의 흐림 정도    NTU               영양염류 농도를 직접
                                                        측정하는 값은 아님

  수온              물의 온도         °C                DO 및 생태 상태 해석에
                                                        참고

  pH                산성·염기성 정도  pH 단위 없음      농업 비료 유출의 직접

                                      mm/일             명시
  ----------------------------------------------------------------------------

**중요:** 질산염과 질산성 질소는 같은 수치로 취급하면 안 되며, 인산염과
인산염-인도 서로 다르다. 변환이나 비교를 할 때는 화학종과 단위를
확인한다.

### 3.4 그래프 및 데이터 기록

-   최근 30\~60개 가상 데이터 포인트를 선 그래프로 표시
-   사용자가 지표를 선택해 그래프를 바꿀 수 있게 한다.
-   그래프 축에 단위와 시간을 표시한다.
-   가상 데이터임을 차트 제목이나 범례에 표시한다.
-   현재 세션에서 생성된 값의 CSV 다운로드 기능은 선택 기능으로 둔다.
-   새로고침 후 데이터가 유지되지 않는다면 이를 안내한다. 영구 저장은
    초기 범위에 포함하지 않는다.

### 3.5 위험도 표시

-   위험도는 교육·시연용 규칙 기반 상태이며 공식 수질 등급이나 법적
    기준이 아니다.
-   임계값은 코드에 숨겨진 상수로만 두지 말고 설정 파일 또는 별도 상수
    모듈에 모아 쉽게 수정할 수 있게 한다.
-   임계값이 특정 공식 기준을 인용하지 않는 경우 "시연용 임계값"이라고
    명시한다.
-   하나의 수질 항목만으로 비료 유출 원인을 확정하지 않는다.
-   상태 메시지 예시:
    -   "가상 데이터에서 인산염 값이 설정한 시연용 기준을 넘었습니다."
    -   "영양염류가 높게 나타나는 시나리오입니다. 실제 수질 검사와 주변
        오염원 확인이 필요합니다."
    -   "현재 화면은 가상 데이터이므로 실제 하천 상태를 뜻하지
        않습니다."

### 3.6 설명 및 대응 권고

상태에 따라 다음과 같은 일반적인 대응 정보를 제공한다. - 비료를
작물·토양 검사 결과와 권장 시비 기준에 맞춰 사용 - 강우 직전의 불필요한
시비를 피하고 지역 농업지도기관의 권고 확인 - 하천 주변 식생 완충지대
조성 가능성 검토 - 실제 오염 의심 시 관계 기관의 공식 측정 자료와 현장
검사 확인 - 유출 원인을 단정하지 말고 하수·축산·산업 등 다른 원인도 고려

앱은 자동으로 실제 현장 조치를 지시하지 않는다. "추천"은 정보 제공이며,
실제 조치는 전문가·관계 기관의 판단을 따라야 한다.

### 3.7 시뮬레이션 패널

사용자가 다음 값을 조절할 수 있도록 한다. - 가상 강우량: 낮음/중간/높음
또는 슬라이더 - 가상 영양염류 유입 수준: 낮음/중간/높음 또는 슬라이더 -
식생 완충지대 시나리오: 적용/미적용 - 비료 사용 관리 시나리오:
적용/미적용

변수 변경 결과는 **가상 시나리오 비교**로 표시한다. 임의의 계산식을 실제
저감률이나 과학적으로 검증된 예측처럼 표현하지 않는다. 비교 결과에
"교육용 모델, 실제 현장 효과를 보장하지 않음"을 표시한다.

## 4. 데이터 설계

### 4.1 초기 버전

-   실제 센서나 외부 API에 의존하지 않는다.
-   앱 내부의 가상 데이터 생성기로 동작한다.
-   화면·차트·위험 안내·시뮬레이션 기능을 먼저 구현한다.
-   실제 데이터 연결은 향후 개선 항목으로 둔다.

### 4.2 가상 데이터 구조

각 데이터 포인트는 다음 필드를 가진다.

``` json
{
  "timestamp": "ISO-8601 형식의 시간",
  "stationId": "SIM-RIVER-01",
  "stationName": "가상 하천 지점 A",
  "dataType": "SIMULATED",
  "nitrateMgL": 2.4,
  "phosphateMgL": 0.08,
  "dissolvedOxygenMgL": 7.6,
  "turbidityNTU": 4.2,
  "waterTemperatureC": 19.5,
  "pH": 7.2,
  "rainfallMmPerHour": 1.0
}
```

위 숫자는 데이터 형식을 설명하기 위한 예시값이며 실제 측정값이나 공식
기준이 아니다. 앱은 실제 데이터와 가상 데이터를 섞어 표시하지 않는다.

### 4.3 미래의 실제 데이터 연결을 고려한 설계

-   데이터 처리와 UI 코드를 분리한다.
-   데이터 제공 방식에 상관없이 화면에서 공통으로 사용할 표준 데이터
    구조를 정의한다.
-   데이터 출처, 측정 시각, 측정 지점, 단위, 데이터
    종류(실측/가상/예측)를 저장한다.
-   CSV 파일을 나중에 연결할 수 있도록 열 이름 매핑과 유효성 검사를
    설계한다.
-   API를 추가할 경우 브라우저에 비밀 API 키를 노출하지 않는다.
-   기관별 데이터의 단위, 시간대, 결측값, 측정 주기가 다를 수 있으므로
    변환 규칙을 문서화한다.

## 5. AI 사용 범위

### 5.1 초기 버전에서 구현할 것

-   실시간처럼 보이는 가상 데이터 생성
-   규칙 기반 상태 분류
-   그래프와 추세 시각화
-   선택한 가상 조건에 따른 시나리오 비교
-   상태에 따른 설명과 예방 권고

### 5.2 초기 버전에서 AI라고 과장하지 말 것

초기 버전은 실제 센서 자료로 학습한 머신러닝 모델이 아니다. 따라서
가상값 생성이나 규칙 기반 위험도 계산을 "AI가 실제 오염을 예측했다"고
표현하지 않는다. 프로젝트 이름에 AI를 사용하더라도 화면에서 어떤 기능이
AI이고 어떤 기능이 규칙 기반인지 명확히 설명한다.

### 5.3 향후 AI 모델을 추가하려면

-   신뢰할 수 있는 실제 수질·강우·유역 자료 확보
-   데이터 정제 및 학습·검증·테스트 데이터 분리
-   예측 목표와 시간 범위 정의
-   모델 성능 측정 및 기준 모델과 비교
-   예측 오차와 적용 범위 표시
-   데이터가 부족하면 예측 모델을 구현했다고 주장하지 않는다.

## 6. 화면 구성

### 화면 1: 대시보드

-   앱 이름과 간단한 설명
-   눈에 잘 띄는 가상 데이터 안내 배너
-   지표 카드
-   최근 추세 그래프
-   위험 상태와 근거
-   마지막 갱신 시간 및 일시 정지/재개 버튼

### 화면 2: 수질 데이터 상세

-   지표 선택
-   시간 범위 선택
-   시계열 차트
-   최근 데이터 표
-   CSV 다운로드(가능할 경우)
-   가상 데이터 라벨

### 화면 3: 시뮬레이션

-   강우량·영양염류 유입·대책 적용 여부 조절
-   기준 시나리오와 대책 적용 시나리오 비교
-   결과는 상대적·가상적 변화로 표시
-   실제 저감률처럼 오해할 표현 금지

### 화면 4: 해결 방안 안내

-   비료 사용 관리
-   식생 완충지대
-   실제 수질 확인 절차
-   데이터 해석의 한계와 참고 기관 안내

### 디자인 원칙

-   깔끔한 환경·과학 대시보드 스타일
-   색상만으로 위험도를 전달하지 말고 텍스트와 아이콘도 함께 사용
-   모바일과 데스크톱 화면에 대응
-   단위와 데이터 출처를 명확히 표시
-   가상·실측·예측값을 서로 다른 배지와 라벨로 구분
-   그래프에 제목, 축, 범례, 시간 정보를 표시
-   로딩·오류·데이터 없음 상태를 구현

## 7. 기술 및 배포 요구사항

### 7.1 개발

-   Google AI Studio에서 생성한 웹 프로젝트를 기준으로 구현한다.
-   프로젝트가 사용하는 프레임워크와 실행 명령을 README에 명시한다.
-   코드 구조는 데이터 생성, 데이터 처리, 위험도 계산, UI를 가능한 한
    분리한다.
-   비밀 키나 개인 정보는 소스 코드에 포함하지 않는다.
-   불필요한 외부 서비스 의존성을 최소화한다.

### 7.2 GitHub

-   소스 코드와 PRD.md, README.md를 저장한다.
-   불필요한 빌드 산출물과 비밀 키는 저장하지 않는다.
-   `.env` 파일에 비밀 정보가 있다면 저장소에 올리지 않고 `.gitignore`에
    추가한다.
-   공개 데이터 파일은 사용 조건과 라이선스를 확인한 후 포함한다.

### 7.3 Vercel

-   GitHub 저장소를 연결해 배포한다.
-   프레임워크에 맞는 빌드 설정을 사용한다.
-   필요한 환경변수는 Vercel 프로젝트 설정에 등록한다.
-   배포 후 실제 URL에서 주요 기능을 확인한다.
-   브라우저 전용 프로토타입이라면 별도 서버나 데이터베이스 없이도
    작동하도록 구성할 수 있다.

## 8. 테스트 및 완료 기준

### 기능 테스트

-   [ ] 앱이 오류 없이 열린다.
-   [ ] 가상 데이터가 설정된 간격으로 갱신된다.
-   [ ] 일시 정지·재개·초기화 버튼이 작동한다.
-   [ ] 지표 카드와 그래프 값이 일치한다.
-   [ ] 그래프 축과 단위가 표시된다.
-   [ ] 시뮬레이션 설정 변경이 결과 화면에 반영된다.
-   [ ] 가상 데이터라는 안내가 항상 보인다.
-   [ ] 위험 안내가 실제 오염 원인을 확정하지 않는다.
-   [ ] 모바일과 데스크톱에서 레이아웃이 깨지지 않는다.
-   [ ] Vercel 배포 URL에서 주요 기능이 동작한다.

### 데이터 정확성·안전 테스트

-   [ ] 음수 농도나 불가능한 값이 생성되지 않는다.
-   [ ] 데이터가 가상값임을 실제 측정값으로 오인하지 않도록 표시한다.
-   [ ] 임계값이 공식 기준이 아니라면 시연용 기준이라고 명시한다.
-   [ ] 질산염과 질산성 질소, 인산염과 인산염-인을 혼동하지 않는다.
-   [ ] 시뮬레이션 결과를 실제 현장 저감률로 표현하지 않는다.
-   [ ] 실제 데이터 연결 시 출처·단위·측정 시각을 기록한다.

## 10. AI Studio 구현 지시

이 PRD를 기준으로 우선 작동 가능한 웹앱을 구현한다.

1.  프로젝트의 기술 스택과 파일 구조를 먼저 확인하고, 해당 환경에서 실행
    가능한 코드를 작성한다.
2.  가상 실시간 데이터 생성기를 구현하고 모든 가상값에 `SIMULATED`
    라벨을 붙인다.
3.  대시보드, 그래프, 위험 안내, 시뮬레이션 화면을 구현한다.
4.  데이터 생성·처리·시각화 코드를 분리해 나중에 실제 데이터 소스로
    교체하기 쉽게 만든다.
5.  실제 센서나 외부 API가 연결된 것처럼 가장하지 않는다.
6.  임의의 시뮬레이션 수치나 임계값을 과학적으로 검증된 사실처럼
    표현하지 않는다.
7.  README.md에 설치·실행·빌드·배포 절차를 작성한다.
8.  코드 작성 후 완료 기준 체크리스트를 검토하고, 미구현 항목을
    명시한다.
9.  GitHub와 Vercel에서 배포 가능한 형태로 구성한다.
10. 필요한 경우 단계별로 구현하고, 각 단계에서 실행 오류를 점검한다.

## 11. 성공 기준

이 프로젝트의 첫 번째 성공 기준은 실제 오염을 정확히 진단하는 것이
아니라, 가상 데이터가 실시간으로 갱신되는 모습을 시각화하고, 수질 지표의
변화를 설명하며, 가상 조건에 따른 대응 시나리오를 사용자가 이해할 수
있도록 보여주는 것이다. 실제 수질 관리에 활용하려면 검증된 측정 데이터와
과학적으로 검증된 분석 모델을 추가해야 한다.
